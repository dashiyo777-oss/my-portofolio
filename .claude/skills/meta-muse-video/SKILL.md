# Meta Muse 動画制作スキル

> 出典：YouTube「【Meta Muse動画生成】プロンプトのみで実写風・アニメ風動画を作る方法！AIエージェントにワークフローを任せて自動生成する方法を解説」（AI共創イノベーション／ワンダー佐藤、20分56秒）。字幕の文字起こしと、動画内で映された解説スライド「生成クリップ組み合わせ動画の作り方」（全10枚、Museが作成）をもとにまとめた。
> 動画とスライドの内容（事実）と、このスキルで補ったもの（★補足）を分けて書く。Museの機能や制限は変わりやすいので、使う前に実機で確かめる。

---

## 0. 考え方：生成と組み立ての分業

**大原則（スライド2/10）**
- **尺と同期は、すべて実測値から決める。**
- **生成AIは素材作り、構成と仕上げはコードが担う。**
- だからスタイルや尺を変えても、同じ手順で作れる。
- 工程ごとに成果物ファイルが残るので、途中から再開できる。

**Museでできること（動画の説明）**
- Museの中には**クラウド上の仮想PC**があり、Python で動画のトリミング、音声の削除、連結、ズーム、テロップ合成ができる。それを**チャットのプロンプトだけ**で頼める。
- 動画クリップは**1本約10秒、延長はできない**。生成物は**音声付き**で返ってくる。だから10秒の素材を何本も作り、音を消してつなぐ。
- 映像に日本語をしゃべらせると間違えやすい。**音声は別に作る（ポッドキャスト機能や読み上げ音声）と日本語が正確になる。**
- 実例：59秒の実写風の解説動画（クリップ6本）、同じ内容のアニメ版、3分の解説動画（動画クリップとイラストとコードによる動きを全部組み合わせたもの）。
- スライドも作れる（「10枚作って」で10枚。PDF、PowerPointにもできる）。動画作者は、Museが作ったスライド（pptx）をGoogleの動画編集ツールに読み込んで、ナレーション付きの動画にもしていた。

使いどころ：メインチャンネルの主力作品より、**サブチャンネル、解説動画、リール、ショート**向き（動画作者の評価）。

## 1. 8つの工程と数値

### Step 1　台本を作る
- 構造：**セクション × セリフ行の2階層（JSON形式）**。
- **1行＝1セリフ**が、以後の全処理の最小単位。
- **セクションの題名が、そのまま画面の見出し**になる。
- 記述ルール：**1行は40字前後まで**（テロップが1行に収まる目安）。**声は話者ごとに固定**。
- 尺の目安：**約6.3字／秒（1分≒10行、3分≒30行）**。
- ここを一番しっかり作り込む（台本がないと何も始まらない）。

★補足：台本JSONの例
```json
{
  "title": "1分でわかる Meta Museの使い方",
  "sections": [
    {
      "heading": "Museとは",
      "lines": [
        {"speaker": "Alex", "text": "ミューズはメタのパーソナルAIエージェントです。"},
        {"speaker": "Mia",  "text": "専属アシスタントとして働きます。"}
      ]
    }
  ]
}
```

### Step 2　音声を先に作って実測する（音声先行）
- 映像より先に音声を作ると、**その長さが全体の時刻基準**になる。あとから尺を合わせる作業が、原理的に消える。
- **行ごとに音声を生成し、長さを実測して並べる。**
- 間隔：**冒頭0.5秒／行間0.35秒／セクション間0.8秒**。
- 極端にゆっくり読まれた行は、**言い換えて作り直す**。
- 動画の実例はポッドキャスト機能の2人の声。1人で読み上げたいときは、Museの仮想PCに無料の読み上げ音声を入れて使う方法もある。

### Step 3　文字起こしを作る
- **タイムスタンプ付き文字起こし**。例：`[00:12.33 - 00:16.72] Alex：使い方は簡単です…`
- 全行について「**いつ・誰が・何を**」話すかを記録する。
- これは音声認識ではなく、**「台本×実測時刻」の対応表**。だから**テロップの文言と音声が構造的にズレない**。
- この文字起こしが、次の分割計画の入力になる。

### Step 4　分割計画を立てる
- **貪欲法で区切る**：行を足していき、**上限11.5秒を超える所で切る**。
- クリップの本数 ≒ **ceil(総尺 ÷ 10)**。
- 実績：**59秒 → 6本（11.0／11.0／6.0／11.4／9.1／6.3秒）**。
- **生成は1回あたり6本まで。** 長尺は複数回に分けて生成する。
- 区間ごとに「何の場面か」が決まり、それが生成の指示書になる。この計画はAIに考えさせてよい。

### Step 5　クリップを生成する
**プロンプトは3層構造**
1. **共通スタイル文**：画のトーンを統一する（全クリップ同じ文）
2. **場面の内容**：その区間のセリフに合う映像
3. **事故予防の一文**：文字は抽象的に、など

**一貫性のコツ**
- **キャラクターの描写文は、全クリップで同一**にする（キャラクターを固定しないなら不要）。
- 画面の文字は「**判読できない抽象UI**」と指定する（AIが崩れた文字を描く事故を防ぐ）。
- 生成物は約10秒・音声付きで返る（音声は後で除去する）。
- 動画クリップとイラストを混ぜると表現の幅が広がる。ズームや静止などの動きはコードで付ける。

★補足：1本分のプロンプトの組み立て例
```
【共通スタイル文】実写風、夜のオフィス、青と紫のネオン、浅い被写界深度、シネマティックな照明、16:9。
【キャラクター描写】30代の男性、黒い巻き髪、無精ひげ、紺のパーカー。
【場面の内容】男性がノートパソコンに話しかけ、画面から光の粒子が立ち上がる。カメラはゆっくり寄る。
【事故予防】画面やモニターの文字は判読できない抽象的なUIにする。字幕やロゴは入れない。
```

### Step 6　無音化して長さを合わせ、連結する
**クリップごとの処理**
- **音声を除去**し、**解像度とfpsを統一**する。
- 区間（窓）より短い分は、**最終フレームの凍結で埋める**。
- 境界は**セリフ間の「中点」**で決め、全尺を隙間なく覆う。

**連結**
- 条件をそろえて再エンコードし、**連結はコピーで無劣化**にする。
- 土台となる「**無音の映像**」がここで完成する。

### Step 7　ナレーションと文字を合成する
**ナレーション構築**
- 各行の音声を**実測時刻に配置**し、重ねて1本にする。
- **末尾を埋めてから総尺に切る**ことで、最後の画面が切れない。

**文字はコードで合成**
- 冒頭：**タイトル画面**（中央に大きく、色分け）
- 最上部：**セクションタイトル**／最下部：**テロップ**
- テキストは**ファイル経由で渡し**、文字化け事故を防ぐ。

### Step 8　検証と仕上げ
**検証の3点セット**
1. **尺・解像度・コーデック**を確認
2. **音量**を確認（**平均 -22〜-20dB** が目安）
3. **フレームを抜き出し**、タイトル・切替・テロップを目視

**応用**
- **スタイル変更は、共通スタイル文の差し替えだけ**（実写風⇔アニメ風）。
- **長尺化は、台本の行数を増やすだけ。**
- 書き出し中のファイルは未完成に見えるため、**完了後に検証**する。
- おかしい場面は**その素材だけ作り直して組み直す**（全部は作り直さない）。
- うまくいったら**スキル化**する。

## 2. 画面の型

| 位置 | 内容 |
|------|------|
| 冒頭 | タイトル画面（中央に大きく、色分け） |
| 最上部 | セクションタイトル（台本のセクション題名） |
| 中央 | 生成クリップ／イラスト（背景にキャラクター） |
| 最下部 | テロップ（タイムスタンプ付き文字起こし） |
| 音声 | ナレーション（ポッドキャストの2人の声、または読み上げ音声） |

アニメ風にするときも、この型はそのまま。**変わるのは共通スタイル文とキャラクター描写だけ。**

## 3. Museに渡すプロンプトのテンプレート

動画作者によると、最初のプロンプトは「やり方を順番に書くだけ」の短いものでよい。以下は、スライドの手順をそのまま指示文にしたもの（★補足：文面はこのスキルで作った。動画で使われたプロンプトの原文ではない）。

### 3-1. 一括指示（最初の1本）

```
次の8工程で、約【60】秒の解説動画を作ってください。テーマは【テーマ】です。
尺と同期はすべて実測値から決め、生成AIは素材作り、構成と仕上げはコードで行ってください。工程ごとの成果物はファイルで残してください。

1. 台本：セクション×セリフ行の2階層でJSONにする。1行は40字前後まで、話者ごとに声を固定。約6.3字／秒（1分≒10行）で行数を決める。
2. 音声：行ごとに読み上げ音声を作り、長さを実測して並べる。間隔は冒頭0.5秒、行間0.35秒、セクション間0.8秒。極端に遅い行は言い換えて作り直す。
3. 文字起こし：台本と実測時刻の対応表として、タイムスタンプ付き文字起こしを作る（いつ・誰が・何を）。
4. 分割計画：行を足していき、11.5秒を超える所で切る。区間ごとの場面を決めて、表で見せる。
5. クリップ生成：区間ごとに約10秒の動画を作る（1回6本まで）。プロンプトは次の3層。
   共通スタイル文：【例：実写風、夜のオフィス、青と紫のネオン、シネマティック、16:9】
   場面の内容：その区間のセリフに合う映像
   事故予防の一文：画面の文字は判読できない抽象UIにする
   キャラクター描写（全クリップ同一）：【例：30代の男性、黒い巻き髪、紺のパーカー】
6. 連結：各クリップの音声を除去し、解像度とfpsを統一。短い分は最終フレームの凍結で埋める。境界はセリフ間の中点。再エンコード後、コピーで無劣化に連結して無音の映像を作る。
7. 合成：各行の音声を実測時刻に配置してナレーションを1本にする（末尾を埋めてから総尺に切る）。冒頭にタイトル画面（中央に大きく、色分け）、最上部にセクションタイトル、最下部にテロップをコードで合成する。テキストはファイル経由で渡す。
8. 検証：書き出し完了後に、尺・解像度・コーデック、音量（平均-22〜-20dB）を確認し、フレームを抜き出してタイトル・切替・テロップを見せる。

書き出し先：【Googleドライブの〇〇フォルダ】に、完成動画と素材をまとめて保存する。
```

### 3-2. 部分修正

```
【セクション3】のクリップがおかしいので、そのクリップだけ作り直して組み直してください。ほかはそのままにしてください。
```
スクショを添えて「この場面だけ変えて」と頼んでもよい。

### 3-3. スキル化（うまくいったら）

```
今回の動画の作り方を、次回から同じ手順で作れるスキルにしてください。8工程の数値、画面の型、共通スタイル文、キャラクター描写を含めて、Googleドライブの【〇〇】に保存してください。
```
これで**次回からプロンプトは「テーマ」と「長さ」だけ**でよくなる（動画作者はzipでGoogleドライブに保存していた）。

### 3-4. 作り分け（スキルを使って）

```
さっきのスキルで、同じ内容をアニメ風にしてください。共通スタイル文をアニメ調に差し替え、キャラクターは【この2人】にしてください。
```
```
さっきのスキルで、【テーマ】の3分の動画を作ってください。台本は約30行にしてください。
```

## 4. 進め方と注意

1. **まずは普通の、オーソドックスな動画を1本作って様子を見る。** 応用（スタイル変更、イラストやコードの動きを混ぜる、長尺化）はその後にする。
2. **書き出し先は必ず指定する。** 指定しないとクラウドの中に残って、どこに行ったか分からなくなる。長く残す素材は、**素材ごとGoogleドライブに保存**する。
3. 生成映像は**ときどき崩れる**。Step 8 の目視チェックを省かない。
4. 一番のコツは**ナレーションと文字のタイミングを合わせること**。ここさえ押さえれば、プロンプトの書き方は自由でよい（動画作者の言葉）。

## 5. このプロジェクトでの使い方（★補足）

- **公開前の確認**：ナレーションや台本は `knowledge/professional-writing-blueprint.md` の倫理に従う。嘘を売らず、一次情報で確かめる。AIで生成した実写風の人物を、実在の人物や体験談のように見せない。
- **楽曲配信の説明文**に動画の紹介文を流用するときは、CLAUDE.md の表記ルールに従い、ダッシュやハイフン類を使わない。
- **歌詞MV**（`*-lyric-mv.mp4`）やプロモ動画（`sae-hana-awase-promo.mp4` など）にも同じ流れが使える。曲の場合は、Step 2 の音声の代わりに**楽曲ファイルを時刻基準**にし、歌詞1行を台本の1行として扱う。Step 4 の区切りは、歌詞の行の切れ目で決める。
